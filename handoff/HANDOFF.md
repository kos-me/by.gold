# gold.by — что осталось сделать (передача в разработку)

Дизайн: `gold.by v2.dc.html`. Все состояния собраны в одном файле,
переключатели для ревью — внизу страницы («состояние: данные подтверждены / срок истёк»).

## 1. Данные (главное)

Все цифры в макете — заглушки. Нужен один источник истины:

```
decree: { number: "41", date: "2026-07-03", validUntil: "2026-07-31",
          sourceUrl: "https://minfin.gov.by/...",
          prices: { 375: 101.55, 500: 135.40, 585: 158.42, 750: 203.10, 958: 259.43, 999: 270.60 } }
```

- **Правило состояния:** `today > validUntil` и нет постановления с более поздней датой
  → страница уходит в состояние «срок истёк» (в макете флаг `withheld`). Цена скрывается,
  калькулятор выключается, последняя известная цифра показывается только как архив.
- Проверка источника — раз в час (текст в макете это обещает: «проверяем каждый час»).
  Время последней проверки выводится в футере и в клейме, брать из реального лога, не из даты сборки.
- История: массив прошлых постановлений (номер, период, цена 585) — питает и таблицу, и спарклайн.
- Слитки НБРБ — отдельный источник, обновление ежедневное. Регламент другой, смешивать нельзя.

## 2. Шрифты

Сейчас Google Fonts с CDN — заменить на self-hosted woff2 с сабсетом:

- `Onest` 700/800 — заголовки и числа
- `Golos Text` 400/500/600 — текст
- `Martian Mono` 400/500 — микротекст клейма и лейблы. **Проверить кириллицу** перед фиксацией;
  если к/ж/д/б окажутся слабыми — заменить на `Martian Mono`-альтернативу с полным набором.

Сабсет: cyrillic + latin + цифры + `№ — · ×`. `font-display: swap`, preload только для Onest 700.

## 3. Изображения

В проекте лежат готовые кропы (webp, 900px по ширине, вместе ~54 КБ):

| файл | где | вес |
|---|---|---|
| `images/hallmark-585.webp` | главная, между ценой и калькулятором | 9 КБ |
| `images/touchstone-assay.webp` | главная, низ | 28 КБ |
| `images/scale-display.webp` | /kak-proverit-otsenku, после шагов | 17 КБ |

Оригиналы — в `uploads/`. Что нужно от разработки:

- `loading="lazy"` на все три, `decoding="async"`; первый кадр не входит в LCP, приоритет не нужен.
- Осмысленные `alt`: «оттиск 585 и пробирное клеймо внутри шинки кольца», «капля реактива на пробирном
  камне», «дисплей поверенных весов, 10,12 г».
- **Лицензии не проверены** — кадры взяты заказчиком из интернета. До продакшена либо подтвердить право
  на использование, либо переснять. Третий кадр — обрезка каталожного фото весов, у него это критично.
- Если появится своя съёмка: клеймо горизонтально, оттиск левее центра; опробование — плотно на камень
  и наконечник пипетки; весы — включённый дисплей с граммами, ношеная вещь, без красных витрин.

## 4. Форма сообщений об ошибке (/o-proekte)

Состояния нарисованы: `idle`, `invalid`, `sending`, `sent`, `dupe` («уже в работе»), `failed`.
В макете развилка имитирована: `.test` в адресе → сбой, «41» в тексте → дубликат.

Реальный контракт:

```
POST /api/report  { email, note }
200 { status: "accepted", ticket: "GB-1748" }
200 { status: "duplicate", decree: "41", since: "2026-07-28", count: 3 }
4xx/5xx → состояние failed, текст пользователя сохраняется в форме
```

- «Дубликат» определяется по номеру постановления, упомянутому в тексте или активному на момент отправки.
- Антиспам без капчи: honeypot + rate limit по IP. Капча ломает тон страницы.
- Ответ приходит на почту; `ticket` показывается, чтобы человеку было на что ссылаться.

## 5. Мелочи

- Утверждение «ювелирные сети иногда платят выше» ничем не подкреплено. Либо ссылка на условия
  двух-трёх сетей, либо формулировка мягче.
- Проверить 360px: таблица проб, спарклайн и «может быть больше» должны переноситься, а не скроллиться.
- `prefers-reduced-motion` и `:focus-visible` в макете уже заданы, при переносе не потерять.
- Абзац «кто ведёт проект» на /o-proekte сознательно пропущен заказчиком.
